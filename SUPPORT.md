# Support

## Where to Start

This project is maintained as an applied browser-game and agent-engineering reference. Use the repository’s public issue forms for reproducible defects and focused feature proposals. Before opening an issue, review the [README](README.md), [CONTRIBUTING.md](CONTRIBUTING.md), and existing open issues to avoid duplicates.

| Need | Best route |
| --- | --- |
| Reproducible gameplay, rendering, or build defect | Open a **Bug report** using the repository issue form. |
| Focused improvement or new capability | Open a **Feature request** using the repository issue form. |
| Setup, contribution, or validation question | Start a GitHub Discussion if enabled; otherwise open an issue titled `question:` with the relevant logs and environment. |
| Behavior or participation concern | Report privately using the contact path described in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). |
| Security vulnerability | Follow [SECURITY.md](SECURITY.md). Do not disclose it publicly. |

## Effective Requests

A helpful report identifies the browser and operating system, the game mode or URL parameters used, exact steps, expected and observed behavior, and console output or screenshots when relevant. Visual and interaction defects are easier to triage with the quality tier, input method, and whether reduced motion was enabled.

## Maintainer Boundaries

Support is provided on a best-effort basis. The project does not provide a hosted backend, account recovery, data restoration, commercial service-level agreement, or support for unverified third-party modifications. Local progression is stored in the browser and may be cleared when browser storage is removed.

## Disclosure Reminder

Do not post credentials, API keys, personal data, private URLs, or unredacted browser profiles in an issue or pull request. The documented `QA_URL` setting should reference only a local or non-sensitive preview address.
